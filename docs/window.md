# The window's chrome

About `crates/emaki-app/src/workbench.rs`, `main.rs` and `ui_state.rs`: the strip buttons, the sidebar, the sessions page, the layout, the settings window, menus and rename, tabs, focus, scroll routing, what the window remembers.

## Rules

- Every click the window swallows goes through `swallow_click`. The toolkit's selection layer begins a text drag on every left mouse-down and ends it on the bubble-phase mouse-up; a handler that stops propagation eats that mouse-up and every later mouse move extends a selection. The release can also go where no handler of ours is: a press on a Windows window's frame reaches the window as a mouse-down, and the system's resize or move then keeps the release. So the layer also ends a drag at the first move with the left button up (UPSTREAM 44), and a drag of our own (an edge, a band) checks `pressed_button` on every move and lets go when it is not the left.
- A sheet on a scrim that closes at a click occludes (`.occlude()` on the sheet, not only on the scrim). gpui counts a click where the press and the release are both in an element's bounds and the element is under the pointer both times, and a scrim's bounds take its sheet in: a press in the sheet let go outside it, or the other way, closed the sheet, as a selection dragged past a field's end does. Occluding, the sheet keeps the scrim from being under the pointer while the pointer is over the sheet. Rename, search, the comparison, the branch sheets, the sign-in sheet, the lightbox and the floating sidebar all do.
- A hover style that changes the text's color is set whatever state the element is in, never under a `when`. gpui works the text's color out at layout from a flag it keeps per element, and that flag hears the pointer leave only while a hover style is set. Taken off an active segment, the flag stayed "over", and the segment came back to rest lit with the pointer elsewhere. A hover that changes a ground or a border is painted from where the pointer is and has no such trap.
- Every input the window owns sits in a `div` that `track_focus`es the `InputState`'s handle and carries the text role. The toolkit's input frame tracks a handle of its own, so focusing a state from code lands on a handle with no dispatch node: no key bindings, nothing for assistive apps.
- What a caret key does in a field is the toolkit's, in `vendor/gpui-component/crates/base/src/input/base`, and so the same in every field there is and will be: in one line, up goes to the start and down to the end, and ⇧ with either selects to there. A key that does nothing in a field is looked for there, in the bindings and the `on_action` list (which was missing the selecting pair for one line), not answered in the field's own handler.
- The focused element must be one the page draws. gpui dispatches a key from the focused node, or from the window root when that node is not in the frame, and the root is above every handler in the workbench, so every shortcut goes nowhere.
- ⌘W is one global `CloseTab` binding. A context-bound one loses to a global binding whenever the focus is in the composer. A part of the window that wants ⌘W for itself answers `CloseTab` on its own focused element, as the terminal panel does; a second ⌘W binding in its context is never reached.
- ⌘W closes the nearest thing, in this order: with the keyboard in a shell, that shell's tab and nothing else, even with none left to close; otherwise the comparison of changes when it is up (and the question over it before that), a file shown beside the conversation, then the session's tab, or on a page the page tab while a session is open to go to, then the window (`close_nearest`).
- A `CloseTab` or `CloseWindow` no view heard is handed to the workbench by `main.rs` (`with_workbench`), never answered by closing the window. The focus can be on nothing the page draws, and the key then comes from the window's root: closing there closed the window with tabs open and asked nothing about a file not saved.
- Nothing has to give the focus back when it goes. `keep_focus`, at every draw, asks whether the focus is inside what the workbench drew (`contains_focused` on its own handle). When it is not at one draw and still is not at the next, with the same thing holding it, the focus goes to the composer where one shows and to the workbench's handle where none does. That covers a file closed with the keyboard in it, a field put away, a panel folded, and whatever is added later. It waits a draw because a thing focused as it first appears is in no frame yet.
- A file's pane closed with the files panel beside it gives the keys to the tree (`tree_focus_back`): the file's row is still lit there, and ⌘⌫, ⌘C and the arrows are the tree's only while it has the focus. Not when the composer is being typed in.
- Keep `on_reopen` in `main.rs`. The app stays running with no window, and without the handler a Dock click does nothing.
- One hub for as long as the app runs (`AppHub`, `Hub::attach`). A window closed and opened again takes up the hub there is, with its hidden terminals, drivers and turns, which went on while no window was open; only Quit ends them. Each window had made a hub of its own, and the one left behind went on scanning, with hidden terminals the new window took for a terminal of someone else's, so a message sent to such a session started a second Claude Code on it.
- Every scroller in the window, now and later, has the same bar and keeps its own wheel. Both halves hold for a list, a box, a card, a menu, a page: anything that scrolls up and down.
  - **The bar** is the toolkit's `vertical_scrollbar` on the scroller's handle and nothing else. It shows while the scroller moves, stays one second after the last movement and fades over half a second (the vendored `scrollbar.rs`). No scroller goes without one and none draws its own. The file editor's is that bar made as wide as the strip of marks it runs over (`docs/panels.md`); nothing else changes its width.
  - **A gesture belongs to the scroller it began in**, its momentum included, wherever the pointer is carried: it never scrolls anything else, and stops at that scroller's edge. So a scroller is known to `route_scroll`, one of two ways: as a pane (`Pane`) when it can sit beside another, or by naming itself as it is drawn when it is inside a pane or on a sheet or menu over the window (`inner_scroller` for a handle it has, `kept_scroll` for one it needs; `Inner` says which kind). A scroller that does neither leaks: a flick in it scrolls whatever the pointer reaches next.
- Rows inside a scrolling flex column go in a column of their own and never shrink. As direct children each gave up height once the list was longer than the sidebar, and the whole list changed its spacing at a click.
- A tab and the two strip buttons take their press before `drag_region` does (`press_taken`), or a press on them moves the window.
- Read `sidebar_w`, not the constant `SIDEBAR_W`, which is only the width before any drag.
- A rename is Claude Code's to make (`/rename` in the hidden terminal). Nothing here writes to a transcript, and a name kept only in our own file leaves the terminal's resume list on the old title.
- Never type a rename into a running turn; it waits in `renames`.
- A name asked for is never drawn as the session's title before the transcript says it. The title stays the transcript's, with the mark beside it. Typed is not taken: only the index puts a name away.
- The settings window's page is a flex column inside a flex column. A block wrapper around it collapsed the panel to its top band.
- A round in the conversation list is wrapped in an explicit centring parent. The list lays each item out alone, so an auto margin has nothing to push against.
- The lightbox backdrop is `occlude`d so nothing beneath it hears the mouse. A click anywhere off the picture closes it, the bands beside a picture that fits its region one way included: the picture is the part its size fills (`lightbox_on`, the size read from its header), not its region.

## The two buttons beside the traffic lights

The sidebar button and search (`Workbench::render_strip`) are drawn once over the window's top left corner, not inside the sidebar or the top strip. While the sidebar is there they stand in its header beside the traffic lights, which is only room for them, their centers on the lights'. Put away, the sidebar folds to a rail (`render_rail`, `rail_w`): a column on the frame as wide as its icons, holding the two buttons, then New Session, All Sessions, Agents and Projects as icons, and at its foot the app's icon and the person's picture, which opens Appearance as the footer's does. The two buttons move between the header and the rail's head with the sidebar's own motion (`strip_t`), and the rail fades as the sidebar comes over it. The card then starts at the rail's edge and never under the traffic lights, so the card's strip keeps no room for them, and the files panel's button and the outline's stand one over the other whether the sidebar is there or not. On a Mac the traffic lights stand in a column at the rail's head and the rail's icons start under them; they go from gpui's row to the column and back with the sidebar's motion (`sys::fold_lights`). gpui puts them back in its row at a resize, a change of key window or of appearance and more, so the buttons and their title bar container are watched for a move and set again; the container is made as tall as the column, since a button takes a click only inside it, and kept at the window's width, as gpui leaves it: on some Macs the container draws the window's rim and rounded corner at its own edge, and made as narrow as the rail it stood as a notch and a line at the rail's top right, which a Mac without that drawing never shows. A click on the card under it reaches the window, as under gpui's own row. In full screen they are the system's. Tried and dropped: the lights moved toward the window's corner to narrow the rail, which crowded them against both edges. Its empty room moves the window, as the title row does. Tried and dropped: the card reaching the window's edge with the lights over its strip, which set the two buttons, the files panel's and the outline's at four uneven places.

The sidebar comes only by a click on its button or by its key. Tried and dropped: the pointer on the button floating the sidebar over the content, which came up whenever the pointer passed on its way to the rail.

The rail's last entry, Projects, shows the sidebar's Projects card beside the rail (`render_rail_fly`, `rail_fly`), the sidebar's width and the window's height under the title row, on the sidebar's ground. It is the card itself (`render_sidebar_as` with only the card), so its rows, their dots, menus, drags, choosing and keys are the sidebar's. A click outside it, Escape, the button again, the sidebar's button, or a session or page gone to puts it away; it slides out from the rail and fades in, and goes the way it came. Tried and dropped: a tile a project in the rail with a list of its own beside it, which was a second sidebar to keep in step with the first.

Tried and dropped: back and forward arrows after search. The tabs are the way between sessions.

## The sidebar

A name, three entries and a card (`render_sidebar`).

- The wordmark (the app's icon, served as `icon/app.png`, and "Emaki") is in the sidebar's own top strip, right of the two buttons, in `fonts::wordmark_family` and the accent (`theme.primary`), so it follows Settings. Optima has only regular and bold, so the regular is drawn twice half a pixel apart for a weight between. Tried and dropped: serif faces, a bold sans, a fixed gold.
- The strip has no line under it: the sidebar ends against the content's card (Layout). Its foot is still level with the foot of the card's own strip.
- The sidebar stands on the window's frame and draws with a theme of its own (`shell_theme`), as do the two buttons at the window's corner while they are over it. Beside a light page the frame is near black, so that theme has the dark appearance's inks and says it is dark, and whatever goes by the mode picks the shade that reads there. A row is lit and a line ruled in the ink thinned. Everything the sidebar draws takes its colors from that theme: a toolkit button, or a `cx.theme()` inside a closure, brings the page's colors onto the frame, which is how the open session's row came out near white under white words.
- New session, All Sessions, Agents. New session's button, here and in the rail, pressed on the new-session page goes back to where that page was come to from: the session, or All Sessions or Agents, and with that gone the session shown last (`new_toggle`, `new_from`). With the sidebar folded, nothing else on the rail went back to a session without the Projects card. ⌘N only ever opens the page. The All Sessions entry is still ⌘L and `GoSessions`; its icon is a scroll (Tabler's `script`), which is what an emaki is, and does not read as a folder row. Agents is ⌘E and goes to the agents page (`docs/agents.md`).
- One card (`card`), Projects, under a name that does not scroll, taking the height left (`side_scroll`, `Pane::Sidebar` to `route_scroll`).
- The footer is the person's name and a settings gear, nothing else.

The Projects card lists every project, the newest first, and scrolls. It listed ten and then "N more", which went to the sessions page: the card stood half empty and the click left the list for another page. A click opens a folder onto its sessions and closes it again (`folders_open`, kept in `ui.json`): `FOLDER_ROWS` of them, then "N more".

A project can be pinned (the pin beside the plus under the pointer, or a right click on its row; `toggle_pin`, `pinned` in `ui.json`). The row keeps room for the pin and the plus whether they show or not, and a pinned project wears its pin, filled, at all times: a click lets it go. The pinned ones are a block of their own over the rest, in the order they were pinned, with a line at its foot: the rest scrolls under it and the pinned stay where they are. The block takes what it needs up to half the card and past that scrolls by itself (`pin_scroll`), so the rest always has the other half, however many are pinned or open. The wheel moves the block when a gesture begins over it and it has more than shows (`scroll_pins`), and the rest otherwise. One dragged onto another takes its place (`DragPin`, `drag_pin_to`: each pinned row hears the drag and answers when the pointer is on it). `side_order` is the one place the order is made, for the list and for the fitted width. A pin only moves the row: let go, the project is where the index has it.

Several projects are chosen together as the files tree's rows are: ⌘ and a click adds one or takes it out, ⇧ and a click chooses from the one last clicked to this one over the rows as drawn (`side_click_more`, `side_marked`, `side_drawn`), and a rectangle dragged over them from a press anywhere in the card chooses the ones it lies over (`side_band_to`). The card has no empty room to press in, so the press may be on a row: one that has not moved a few points is still that row's click, and the click that ends a drag does nothing (`side_band_live`). A press on a pinned project is its own drag, to another place among the pinned. The rows are not one height here, so each says where it was drawn (`side_rows_at`), cut to its own list. A plain click opens the project and lets the chosen go, as Escape and a click on the card's empty room do. The chosen are lit in the accent, and rows lit one under another in the same list are one block, round at its two ends, unless the upper one's sessions show between them. A press anywhere in the card gives it the keyboard (`side_focus`), and there ⌘A takes every project showing, whatever was chosen: projects, never sessions. Nothing has to be chosen first. A session opened by a click gives the keyboard to its composer, and a letter typed with the card focused goes there too, the keyboard with it, so typing after a click in the sidebar is not lost. A right click on one of several is their menu (`project_menu`), and on any other project its own:

- **Archive Sessions** and **Delete Sessions** ask it of every session of the projects, those the sidebar does not list too (`MenuDo::Sessions`, `manage_ask_of`): the question and the work are the sessions page's (`render_manage_ask`, `manage_now`), and what came of it is said on the notice line. Sessions only: nothing in a project's folder is touched.
- **Open in Finder** opens each one's folder in a window of its own (`projects_do`). More than `OPEN_MANY` at once is asked about first (`render_open_ask`).
- **Copy Path** puts the folder's path on the clipboard, Copy Paths each chosen one's on a line of its own (`project_folder`); a project whose folder is gone has none.
- **Hide Project** puts a project out of the list (`hidden`, kept in `ui.json`); **Show Project** on a hidden one brings it back. A hidden project is not among the pinned while it is hidden, and takes its pin up again when shown. The sessions page lists every project, hidden or not.

Sessions are chosen together in the same ways (`side_sessions`, `side_session_more`, `side_sess_drawn`, `side_sess_at`), across every project that is open: ⇧ and a click reaches over the sessions as drawn, whichever projects they are in. **Projects are chosen or sessions are, never both, and what is touched first says which.** With projects chosen, ⌘ or ⇧ and a click on a session does nothing, and the other way round; a rectangle takes the kind of the row nearest to where it was pressed, once it reaches one, and keeps to it however far it is dragged (`side_band_kind`). A right click on one of several sessions is Archive Sessions when one of them is active and Unarchive Sessions when one is archived, each done to those alone, then Delete Sessions (`side_session_menu`, `archive_items`; a project's menu the same, and the sessions page's Archive is dimmed with no active one chosen); on any other session it is that session's own menu, with Archive Session (Unarchive Session on an archived one) and Delete Session at its foot.

Two sections stand under the last project that shows, each a heading with its count that opens onto its projects in motion (`toggle_section`): "Temporary", then "Hidden". Temporary is the projects every session of which was run in one of the system's temporary folders (`paths::is_temp_dir`): a scratch run of an agent's or a script's, whose folder the system clears and nobody goes back to. A pinned one stays among the pinned and a hidden one is under Hidden. Both sections are shut at every launch and neither is remembered open: they are where what is not wanted in the list goes.

A folder with a live session is open without being asked (`sync_folders`): it opens when one of its sessions goes live and closes when the last stops, if it was opened that way and not clicked since. A click is the person's choice and stays until the folder next goes live or quiet.

A session's mark is in the muted ink unless it is live, so many rows do not read as many colors, and then in its agent's color (`docs/agents.md`, Marks) with a dot in its phase's color. A folder with a live session is in the accent, whichever agent's it is. A folder wears the most pressing of its sessions' (needs you, then working, then your turn).

A folder lists its `FOLDER_ROWS` newest sessions, and under them any older one that has a tab: opened from further back it is in the list while its tab is, and goes with it, growing in and shrinking out as any row does (`side_rows_changed`). The rows have no headings by when ("Today", "Yesterday"); those are the sessions page's.

A session with a tab wears a short bar at its row's left: in the accent for the one showing, gray for the others. The dot at the right is the session's phase and says nothing of tabs.

A folder's sessions unfold and fold over `FOLDER_ANIM`: a box whose height is the sum of its fixed-height rows (`SIDE_ROW_H`, `SIDE_SESSION_H`), which `folder_anim` runs up or down with the opacity. A closing folder is still drawn until the time is up.

Narrower than `NARROW_W` the sidebar leaves the row and comes back only as an overlay over a scrim (the strip button, ⌘⇧B or ⌘B), which any click or Escape puts away. Each of these is in motion (Motion, below). `sidebar_open` keeps the preference for when the window is wide again.

### The sidebar's edge

A strip over the edge (`render_side_grip`, only while the sidebar is beside the content) takes a press (`side_drag`); from then a raw mouse-move listener in the capture phase sets the width to the pointer (`side_drag_to`) and stops the event, so nothing under the pointer hovers or selects. The width (`sidebar_w`, in `ui.json`) stays between `SIDEBAR_MIN`, the least that holds the two buttons and the wordmark, and `SIDEBAR_MAX`. Left of `SIDEBAR_FOLD_AT` the sidebar folds, and comes back in the same drag if the pointer does; the width it had is kept.

A double click goes to the fitted width (`sidebar_fit`): the widest row the Projects card lists, measured with the text system, capped at `SIDEBAR_FIT_MAX`. A row that needs more is a prompt standing in for a title and is cut short at any width; without the cap one long title always asked for the maximum.

## The sessions page

"All Sessions": a row a project, newest first, as the sidebar has them. A project is a folder; the window says "project" and keeps the folder icon. A click opens a row onto its sessions in place and closes it again (`sessions_toggle`, `sessions_open`, kept for the launch only), by the sidebar's motion: a box of fixed-height rows (`PAGE_SESSION_H`) run up or down with the opacity. It went inside the project, to a second level under an "All Projects › folder" line: a click left the list, and two projects could not be looked into at once.

Nothing is headed by when. Each row has the day it was last touched at its right end (`format::day`), a project's before its chevron and a session's in line with it. The one heading is "Archived", over the projects whose every session is archived, kept here alone or in Codex's own archive. A project with a session not archived is above it, and an archived session in one wears an "archived" tag. The pills (All, one per agent) narrow the page.

A project opened by a click, here or in the sidebar, has its foot kept in view as it unfolds (`follow_foot`): where its sessions run past the foot of the list, the list moves up with them, never by more than leaves the project's own row showing. One that opens by itself (a session gone live) moves nothing.

### Choosing sessions

The line over the first project counts the sessions active, archived and in the Trash, each a number in the page's ink and a word in the muted one, the last two only when there are some, with "Select" at its right. It counted each kind's projects too and ran past a narrow page; the list shows the projects. Cut all the same, it fades at its end. Pressed, the line becomes a plate (`manage`, `picked`) and every row gets a box before it. A session's row chooses it; a project's row chooses all of its sessions, and its chevron is then what opens it. The plate has a box for everything the pills leave, the count, what came of the last thing done, and Archive, Delete and Done, drawn as the page's pills are: Archive quiet, Delete in the danger's ink, Done solid as the pill that is on. It is in the list's flow, over the first project; scrolled out of view, a copy of it stands at the page's top (`manage_y`, the "manage-float" presence), so sessions chosen far down can be acted on. It was a strip fixed over the page's title, which read as a toolbar of the window's and not of the list. Each of the two asks first (`render_manage_ask`), and is done off the main thread (`manage_now`).

- **⇧ and a click** chooses every row from the one a plain click last chose to this one, as the page draws them, and adds them to what is chosen (`pick_click`, `pick_anchor`): sessions to a session, across the projects that are open, and projects to a project, each with all of its sessions. From a session to a project, or the other way, it is a plain click: what a range of both takes in is not plain to see.
- **Archive**: the agent does not continue the session until it is unarchived. Claude Code's own copy is let go now, without waiting for it to delete it, and Codex archives its own (`Adapter::archive`, `docs/core.md`). A session archived in Codex itself is archived here too: one word, one meaning, wherever the file is.
- **Delete** puts the session in the Trash, at the foot of the sidebar's Projects card (`emaki_core::trash`, `docs/core.md`). It is done to every session chosen, whatever is running: a turn or a hidden terminal of ours is stopped first, and the deleting waits until each process is gone (`manage_now`); one running in a terminal of the person's goes on there, since nothing is ended in a terminal of theirs, and is in the Trash all the same. A row that stands for a chain of sessions (`continued_in`) is all of them, for every action here (`chains`): deleting the newest alone listed the one before it again.
- **The Trash** lists the deleted sessions as one list, whatever their projects, the last deleted first, each with the days it has left. Under the pointer Put Back takes the place of the days; a right click has Put Back and Delete Permanently, and one on the heading Empty Trash, both asked first. The sessions page has the same list at its foot, under "Trash", whose rows are not chosen with the rest. Put back, a session is as it was before it was deleted and its days are forgotten. Nothing in the Trash is in a project's list, another count or search; it is kept out of `refs` (`trashed`) as the index comes in. The sidebar's is shut at every launch, as Temporary and Hidden are.
- **Unarchive** (a session's menu in the sidebar, Unarchive Session, and a project's, Unarchive Sessions) puts an archived session back for its agent (`Adapter::unarchive`), with nothing asked, since nothing is lost, and nothing counted as running: neither agent takes up an archived session. An archived session cannot be continued until it is unarchived, and the composer says so.
- Both are of sessions. Nothing in a project's folder is touched.
- A session something is running in (`Hub::is_live`, a driver) is left as it is by Archive and counted in what is said.
- The question is not answered from a script: the probe's steps stop at asking.

"N more" under a folder in the sidebar opens that project here and brings the page to it (`sessions_goto`: the row says where it is once drawn); the All Sessions entry goes to the top; the row on an agent's page goes here narrowed to the agent. A right click is Open in Finder on a project and the session's menu on a session.

## Motion

Nothing in the window appears or disappears from one frame to the next. The patterns, each in use and to be used again:

- **A hover's label**: `managed_tooltip`, the toolkit's own, which a `Button` uses: it comes in, and slides to the next element hovered on the same row. Not gpui's plain `.tooltip`, which jumps in and out; a row with both kinds read as two different controls.
- A row under the pointer on a card in the dark appearance is a wash of the ink (a menu's, a list's, the tree's): the palette's own hover is a shade off the card and could not be seen.
- **A menu or a list over the window** (`render_menu`, `render_pick`): it comes in over `MENU_IN`, rising a few pixels into place as it fades in, and goes out over `MENU_OUT`, fading where it was. What was closed is kept for that moment (`menu_gone`, `pick_gone`) and drawn once more with no click taken. Each opening has a serial in its animation's name, so it plays once.
- **A card at the conversation's end** (`render_terminal`, `render_dialog`; `docs/live-turn.md`, The cards): held by its foot, its height opens up from the end and closes back to it, with the gap under it part of what moves, so the conversation above slides and does not jump. What it last showed is kept (`TermShown`, `DialogShown`) to draw it closing. A card whose height is its content's measures itself as it is drawn (`dialog_h`) and takes no room until that is known.
- **A panel at the conversation's side**: its width opens and closes (`docs/panels.md`, `docs/channels.md`). One put away for want of room goes the same way, through the call its button makes (`term_go`, `panel_go`, `outline_show`), never by its flag alone: the flag alone left the button lit and the panel gone between two frames.
- **The layouts** (rendered and CLI): the one comes in where it stands, fading in, while the other fades out over it, out of the row's layout (`layout_seen`, `CLI_ANIM`); the conversation's list is drawn afresh while it fades (Frames). The outline is part of the rendered layout's layer and fades with it. The fade is drawn off the clock on wrappers with no name: a named animation around the layer is a new element at each change, so the outline's own fade-in began again inside it, and the outline stood as an empty gray column while it narrowed by itself.
- **The sidebar**: it stands where it is and fades in as its room in the row opens, and out as it closes, with the card's edge passing over it, whoever asked: its button, the key, a window dragged narrower or wider, a panel that needed its room. `Workbench::render` sees the change (`side_was`) and starts it (`side_anim`); nothing that shows or hides the sidebar has to. It is drawn off the clock (`side_t`, `shown_t`) and not as one element's animation, because the card's left, the panels' left and their edges all stand by the sidebar's width (`side_w_now`, from the rail's width to the sidebar's), and the two buttons at the corner and the traffic lights move between the title row and the rail with it; what the rail does not keep fades, as the rail fades in. Tried and dropped: the sidebar sliding out past the window's edge, which dragged its words off while the buttons it shares with the rail moved to their places. Over the scrim in a narrow window it slides the same way and the scrim fades (`peek_anim`). Not played: a drag of its own edge, and the first draw.
- **A choice that moves** (a segmented control, the pages' buttons in the strip): one plate slides from the old to the new. A panel's button grows its accent line from its middle and shrinks it back (`quiet_mark`).

- **A fold in the conversation** (a tool call's body, a run's calls, a thought, a subagent's rounds): `fold_state` and `fold_wrap`. The box's height runs up from nothing and back, the content fading with it. The content keeps its own height, cut by the box, and says how tall it is as it is drawn. `fold_state` is asked at every draw, shut or open, so a change is seen as one and the first sight of a fold is not played; shut, the content is drawn for that moment more. The room between a fold and its head is inside the fold (`fold_wrap`'s `gap`), in a column with no gap, as it is under a card over the composer: a column's gap outlives a box shut to nothing, and the closing stopped short and then jumped.
- **A row that comes or goes in a list** (a session in a sidebar folder): `side_rows_changed` sets a folder's rows against how they were last drawn. One that was not there grows in; one that is no longer is drawn a moment more where it stood, shrinking (`side_gone`). A folder drawn for the first time plays nothing, and a row that only changes place is not moved in motion.
- **Something small in the sidebar that is there or is not** (the bar of a session with a tab, the line under the pinned projects): `presence`, asked at every draw, which plays a change over `FOLD_ANIM` and not the first sight.
- The settings window draws the workbench's own state (`SettingsView` updates the workbench as it renders), so every listener on it is the workbench's and a change shows in both windows at once. What belongs to a window is made with it (`settings_attach`): the name's field, whose input watches the window it was made in. A list or a menu opened in it (`PickMenu::in_settings`, `Menu::in_settings`) is drawn there and not in the main window, and a field's place is kept by window (`pill_at`): New sessions' lists are the home page's pills' too. Its list keeps a scroll handle of its own: `route_scroll` and the scrollers it knows (`inner_scroller`) are the main window's, by that window's coordinates.
- What the settings window held goes when it closes (`settings_detach`, on the view's release), never on a question first: ⌘W, and Escape with no list open in it, close it from code (`remove_window`), which asks nothing. It closes with the main window. ⌘W or Close Window that reaches no view closes the window it was pressed in: `with_workbench` hands the main window's workbench only to the main window.
- **Something that lies over the window and has no way out of its own** (the rename sheet, the lightbox, the comparison, the branch list and its question, the discard question): `fade_in`, on a static id, which plays once each time it appears. These still go at once.
- **A bar in the flow** (the find bar): its height opens with what is under it moving, by a `max_h` no less than its own.
- **A line under the conversation** (the agent at work, waiting, commands in the background, a card left behind): `foot_line` on its `presence`, keyed by the session so a change of tab plays nothing. It opens up from the composer and closes back, the air over it part of what moves. Going, it is drawn from what it last said, kept for that.
- **A card whose height is its content's** (a permission, a driver's question, the background commands' card): `card_fold`, which measures the card as it is drawn. One answered is drawn a moment more from the request kept, closing, under a layer that takes its clicks.
- **A scroll that a click starts** (the arrows of a dialog's tabs, "Show" for a card left behind, "New messages"): run from where the scroller is, a share of what is left each frame, so it slows onto the place (`tabs_glide_step`, `end_glide_step`, `glide_step`). Never `set_offset` or `scroll_to` straight to the place.
- **Something small whose room stays** (an arrow at a strip's end, the fade there): `presence`, with only its opacity run. The wrapper that plays the fade stays at rest under the name of the last change: taken off when the fade is over, it makes what is inside a new element, whose own animations play again. The outline's old button blinked so, its plate fading in again from the press that had turned the outline on. A button's line grows only from a press a moment old (`pressed_from`) for the same reason.
- **What runs past an edge of a sideways scroller** fades into the ground there (a block of code, a dialog's tabs), and the fade comes and goes with there being more that way.

**Never an animation of no length.** gpui divides by the length to know how far one is, and the debug build stops on a value that is not finite, so `Animation::new(Duration::ZERO)` took the app down (a Markdown file's view, every time it was drawn). An element that animates only sometimes keeps a real length and does nothing in its closure when nothing moves.

**No pause at the end.** A motion runs into its place and stops there, with no hesitation, crawl or second step in its last frames. Every new animation has had one until it was looked for, so look for it. What made them: a box whose width went under its padding, which then stays the padding's (the layout keeps padding and border as a floor), so the last pixels closed at a crawl: scale the padding with the width; a term clamped at zero (`.max(px(0.))`) while the others still ran, so the sum changed slope near the end: make every term of what the element takes up (width, padding, the gap with it, a margin) go to its end in proportion to the one eased clock; a gap or margin outside the box that outlives it; and neighbors that make room only once the element is gone, a second move after the first: they start when it does (`sync_tab_widths` counts a closing page tab as gone).

- **A tab's first read** (`detail_in`): the page is empty under the tabs while the session is read, and what comes then (the folder's line, the conversation, the composer) fades and rises into place over `PAGE_IN`, as a page's content does. The conversation is drawn afresh while it fades, since a kept view replays the opacity it was painted at (Frames). It all came at once on one frame.

Left as they are, on purpose: a change to a tab already read (the conversation is the content, and a cross-fade of two long lists is a blur), text arriving in a live reply, a hover's ground, and a row changing place in a list when its session is written to.

The toolkit's own popover has no way out but at once, which is why a pill's list is ours (`PickMenu`) and not a `Popover`.

A measuring `canvas` laid over an element is `.absolute().inset_0()`. With `.size_full()` alone it stands after the element in the flow, and reports a place one element lower.

## Frames

The window is one view (`Workbench`), and gpui lays out and paints the whole of a view at every frame it draws. Something that moves asks for a frame, so whatever moves costs the window whole, at the rate it asks. What keeps that small:

- **The clock** (`ambient.rs`). What moves for as long as something works (the agent's mark turning, the dots of commands and subagents, an outline row waiting for its label, a spinner) is drawn where the clock stands (`ambient::phase`), and while one was drawn the window asks for the next step (`after_frame`, the last thing a frame paints): about 30 a second, 20 while another app is in use. Never `Animation::repeat` for it: that asks for every frame the display has, and a mark of 14 points turning held the window at 60 frames a second, a fifth of a core and as much again of the window server's, for as long as an agent worked. A transition (a fold, a card coming up) still asks for every frame while it runs, and is over in a moment.
- **Views the window keeps** (`AnyView::cached`): the conversation's list (`transcript::ConversationList`), the sidebar beside the content (`SideView`) and a markdown file as it reads (`panels::FileDoc`). A frame that changes nothing in one replays its last layout and paint; laying out the list in view was most of every frame's work while an agent worked. The list and the sidebar observe the workbench and are drawn afresh whenever it notifies; the file compares what it is drawn from instead (`DocShown`). A view's own content asks for itself too: a list scrolled, a row under the pointer, a fold, a selection.
- **A frame that is not a change** goes through the clock's view (`ambient::redraw`, the terminal panel's screen and its cursor's blink), which draws the window and tells the workbench nothing: a notify of the workbench draws the kept views afresh with it.

The traps of a kept view, each met once:

- What it is drawn from must reach it. gpui draws a kept view afresh only when it or something drawn in it notifies, never when the view around it does: a change the workbench makes and does not notify, or a field kept outside it, leaves it as it was. A text field's keys tell the field, not the view it is in, so the sidebar is drawn afresh while a name is typed in one of its rows (`kept_sidebar`).
- It keeps the opacity it was painted at. Painted while something around it fades, it stays that faint; a fade above the file restarted by a change of tab (the pane is then at another place in the window's tree) left a kept file blank, so the file fades by itself. The list and the sidebar are drawn afresh at every frame of a fade, which asks for frames through the workbench.
- Its text views take part in the window's selection by registering as they paint, and nothing in a kept view paints: `KeptViews` keeps them registered in a frame drawn from the cache (`gpui_component::text::KeptViews`), or the selection layer took them for gone each such frame, cleared them, and the cache was thrown away the next.
- A mark that moves inside it would draw it afresh at every step, so it leaves a place of its size there (`ambient::mark_place`) and is painted over it from outside, on the clock, where the view's last drawing put it (`ambient::Marks`).
- It is laid out at a size it is given, never measured: the list and the sidebar fill their room, and the file is given the height it last measured, so a change of height lands a frame late.

## A session's phase

There was a board, a page of live sessions in four columns; it was removed in v0.1.8 as of little use. What it sorted by is still what the sidebar's dots, the status row and the working mark go by (`Column`, `card_for`): needs you, planning, working, your turn, done.

The phase is `build::turn_state`, a function of the transcript's tail: `stop_reason: end_turn` is your turn, a trailing `tool_use` is working, a trailing `AskUserQuestion` or `ExitPlanMode` needs you, and the latest permission mode says whether working is planning. `peek` computes it for the index from the same tail slice it reads the title from, cached on (size, mtime), so a rescan of every transcript costs nothing.

A phase is shown only for a session with something behind it (`Hub::is_live`): a driver, a hidden terminal, a registered process, or, with none of those, a write in the last ten minutes. Two things keep a dead session from reading as "working" with its clock running, as one killed while a question waited did. A session whose process was registered and is gone has ended (`refresh_peers`). And a Claude Code session that reads as working with no process registered gets a minute and a half, not ten: an interactive one always registers, so it is a headless run of someone's, which writes as it goes, or a process that died before this launch. The sidebar's dot (`dot_of`, which the project's dot, the tabs and the sessions page go by): orange while a question waits; blue while the agent works or something it left running in the background still runs, whichever it is (`background_running`); green, the person's turn, once neither is so, for half an hour from the newest row or from when the dot was last blue, whichever is later (`YOUR_TURN_FOR`, `blue_at`); then none, though a hidden terminal keeps the agent idle behind it. So blue is always followed by green, and blue always means at work: a background command that ends with nothing written still gets its half hour. Tried and dropped: an hour of green, which said "your turn" long after anyone was waiting; ten minutes, too short to come back in; and green while a background command ran, which hid that the session was at work. A question waiting stays as it is, however old. The half hour runs out with nothing written, so the window's clock looks at the dots each second and draws when one has changed (`dots_now`): the dot stayed green past its time until something else drew the window, a key typed in the composer.

- A clip in gpui is a rectangle, so the card is square and its corners are painted over in the frame's color after what it holds (`card_corners`). A panel's ground stood square in a rounded corner otherwise. The card's strip is `FRAME` shorter than `TITLEBAR_H` and starts that much lower, so what is under it is where it was, and the traffic lights and the two buttons are moved down to the strip's middle (`main.rs`, `render_strip`).
- The buttons at the two ends of the card's strip are as far from the card's side as from its top (`STRIP_PAD`).
- Everything readable sits in one column of `CONTENT_W`, centered in what is left of the window: the conversation, the sessions page, the home page.
- The content pane has a top strip with actions on the right.
- The home page is a drawing of a handscroll, an emaki, over a greeting in `fonts::display_family` (the chat font, so titles and the conversation agree), over the composer. The drawing (`home_scroll`) is the scroll seen from the front, as the icon is, with a landscape on its sheet. The landscape is longer than the sheet shows and in four layers by how far off each is (`scripts/home-scroll.py` writes them): mist, a far range, near hills, water. They pass at four speeds. Tried and dropped: a cord hanging from the right axle's foot and swinging with the winding. A handscroll's cord is tied to the stave at its cover's edge, which is wound inside the right roll while it is read, and nothing hangs from an axle.

  - The scroll's own lines (rolls, axles, the sheet's edges, the turns, the sun) are elements with borders: they change width at any moment and are drawn exactly. The landscape is a picture a layer, only moved, inside a box that cuts it to the sheet. Not paths painted a frame at a time: gpui gives a path four samples a pixel (`card_corners`), and lines this thin would step.

The app's icon stood beside the greeting until the drawing did its work; a dark drawing of the icon for the dark appearance was made and dropped, the icon being one thing everywhere.

A press anywhere on the strip drops its list down (`PickFor::Folder`, the one list that never opens upward): the `HOME_FOLDERS` folders worked in last, the chosen one among them even when it is none of those, and under a line "Choose a folder…", a row with no key, which asks the system for any folder (`choose_folder`). ⌘O is that row from the keyboard (`ChooseFolder`), on this page only: on any other page it does nothing. Tried and dropped: a grid of six cards under the composer, and before it full-path pills of every width, which took the page for one choice; a pill beside the mode's on the composer's row, where it read as one more setting of the agent's; and the panel buttons' small track by itself under the card, which belonged to nothing around it.

- Floating cards (composer, search palette, settings) lift with `float_shadow`, a drop in the ink's own hue, not a gray halo.

- The palette is `crates/emaki-app/themes/emaki.json`, one config per appearance, loaded by `install_theme` in `main.rs`. `assets.rs` wraps the toolkit's icon set and serves our own files; nothing draws `mark.svg` now.

## The settings window

⌘, the app menu's Settings…, the gear in the sidebar's foot and a click on the avatar open the settings in a window of their own, as Kotoba's and the Mac's own are (`open_settings`): a rail of sections on the left (`SETTINGS_SECTIONS`; `settings_section` is the one showing) and that section's groups on the right, its name in the window's top, both fading in as the section changes (`workbench/settings.rs`). Opened again, the window comes forward on the section asked for. Its sizes, grounds and controls are in `docs/design.md`, The settings window. The rows scroll under the top (`settings_scroll`), which a section that fits never needs. The window's top and the rail's empty room drag it (`drag_region`); a press on a section does not. Escape puts away a list or a menu open in it, and one goes too when another window is used. A sheet over the main window, with a scrim and a close button, was the settings until v0.2.9: it covered the conversation it set.

A group is a card of rows (`group`, `line`): a name at the left with a line under it where the name does not say it all, the control at the right. A new row is made with `line` in a `group`, never laid out by hand. The widest controls are `CONTROL_W`, so a page's start and end together; a switch, a pill and the avatar stand at their own size at the same right edge. A control at the panel's right with its name a column's width away (one column of names, the controls filling the rest of the row) was the layout until v0.2.8.

What is on or off is a switch (`switch`): the track fills with the accent and the knob slides, over a moment (`presence`), at a press anywhere on it. It took the place of the two words as a choice, On in the green and Off in the red. A tick is for a list of many, where a switch a row would be too much: the formatters, each tick before its name.

The spelling's languages are a row of their own, a flag and two letters each so the five fit, the name on the hover; dimmed and out of the pointer's reach while the check is off.

General's Power group has one switch, off at first: the display is kept on while any session's dot is blue, the agent at work or something it left running in the background, as a release waiting on CI is (`hold_display`, at each pass of the index and each second of the window's clock, and let go when the window's workbench goes: a window closed during a turn had kept the display on for two hours, with nothing left to look at it again; `TurnState::background`, what the index read has seen begin and not end, held against when the agent behind the session started, as the composer's row of background commands is; `sys::hold_display`, an IOKit assertion on a Mac, the thread's execution state on Windows, `systemd-inhibit` on Linux). The system is asked once a change, not at each pass.

An accent's swatch marks the chosen one with a ring inside the disc in the card's ground, so every disc is one size and the row's ends are the first and last disc. The chosen one's name is the row's line.

Text's Size page: a preset (Small, Medium, Large, each of whole points) for every place at once, and under it each place's size: the conversation, the composer, the file preview, the file editor, the terminal (`stepper`). Custom is the person's own set, kept in `config.json` while a preset is chosen and back when Custom is; Medium's sizes until it is first set. The sizes are set under Custom alone; under a preset they are the preset's, shown quiet. A step is a whole point, from a size with a tenth to the next whole one (`TextSizes::step`); a tenth is only typed, in the number's own field with "pt" fixed after it, taken at ↩ or when the field is left (`size_commit`), anything else put back. The fields are made with the settings window (`size_inputs`). Under Custom a size not Medium's has a reset beside it that puts it back to Medium's (`size_reset`), coming and going in motion. The faces stay in Fonts. The terminal's line spacing and padding were rows once; they are the middle step now, set at launch whatever `config.json` says. The terminal's page sends a person to Text's Fonts for its face and to its Size for its size, on a pill that says it.

The sections are nine, in the order a person comes to them: how the window looks (Appearance, Text), what every session is (Conversation, New sessions), what stands around one (Panels, which side each goes on, then Files and Terminal), the keys (Shortcuts), and About last, as a Mac's own settings have it. A section of more than one page has its pages on a segmented control at the right of its name, as Appearance has its language and New sessions its agents (`SETTINGS_PAGES`, `settings_page`, `settings_go`): Text is Fonts and Size, Shortcuts is Window and File editor. Each page fits the window as it opens, and a page's name finds it from anywhere (`settings_place`: `EMAKI_SETTINGS=size`, a link from Terminal to Fonts). Fonts and Text Size were merged as pages, being one subject; Panels, Files and Terminal were pages of one section for a moment and read better as three. Composer was merged into Conversation and Updates into About in v0.3.0.

Conversation has four groups, each under its name. Agent: how a run of tool calls is drawn (folded into one row or not, `docs/conversation.md`). Composer, then Spelling and grammar: the composer's. On-demand model calls: the two helpers that are a small model's calls on the person's account, a switch each with no line under it, both on until turned off: Explain tool calls (`explain.enabled`, `docs/core.md`) and Outline panel (`app.outline`, `docs/panels.md`).

Panels is a picture of the window over two choices, Side panels and Margins, each the pair's two names in the order they stand from left to right (`panels_rows`, `files_side` and `outline_side` in `config.json`). A choice moves the picture's pieces to their sides (`sides_anim`), and the window itself is drawn so at once: the row of side panels and the margins mirrored (`docs/panels.md`, Sides).

Files has Format on save and its languages.

Shortcuts is the commands whose keys may change, in two lists chosen at the right of the section's name as Appearance has its language: the window's, in two groups, Sessions and Panels, and the file editor's, the Sublime Text commands used most, in two groups, Lines and Text (`shortcut_editor`). A group is a card of rows, as every section has, two commands to a row parted by a hairline: the name at the left and the keys at the right on caps (`key_cap_sized`; `shortcut_rows`, `shortcut_cell`). Tiles of keys over names were tried first: two lines an entry, and the right of each tile empty. A press on a command waits for new keys: its keys become a field in the accent that says to press a shortcut and shows the modifiers held as they are pressed, and a press anywhere else, Escape, another section or another window stops the wait. The keys are taken before any binding hears them (`cx.intercept_keystrokes`, `shortcut_key`), so the command's old keys or another's do nothing while it waits. A shortcut is one modifier or several, ⌘ or ⌃ among them (Ctrl or Alt off a Mac), with a letter, a digit or a mark, or with an arrow, Return, Tab, Space, Backspace, Delete or a page key; or a function key, alone or not (`shortcuts::recorded`). A key that lacks ⌘ or ⌃ says so in the name's place for a moment, and a modifier alone waits. A new key is one keystroke, never a chord, though a chord the editor began with is drawn as its two strokes. Nothing is let through that would make two things of one key (`shortcuts::conflict`): another command's keys in either list (a window's key the editor's text also had would be dead there, and the other way round), a key that begins another's chord (⌘K, before ⌘K ⌘U), the window's keys that do not change (copy, paste, cut, select all, undo, redo, find, save, close, quit, Settings, send, the tabs' numbers, hide, minimize, full screen: `shortcuts::TAKEN`), the keys the terminal reads itself rather than through a binding (⌃ and a key, ⌘ with an arrow, Backspace, Delete, Return or a page key, ⌘⇧[ and ⌘⇧], a function key; `terminal_reads`), and any other binding in the keymap, the text fields', a list's, a menu's or Sublime Text's in the editor. The name's place says for a moment what has the keys. A command may always take its own keys back, though another shares them by design (⌘L, All Sessions and the editor's Expand to Line). A command whose keys were changed has a button before them that puts its own back, coming and going as Size's reset does.

The commands, their keys to begin with and their actions are `shortcuts::GROUPS`; what is chosen is `app.shortcuts` in `config.json`, by the command's id, only where it differs. `shortcuts::bindings` makes the bindings of them, the editor's under its text's context, and stands first in `main::key_bindings`; a change makes the keymap again in place (`shortcuts::rebind`): every binding of a command's action under the command's context is taken out (the toolkit binds some editing actions in every field, which stay) and the new ones put where the first stood, so every other binding keeps its rank, and the menus are made again for the keys they name. Clearing the keymap and binding it from scratch would drop the toolkit's own keys, which its `init` binds. Every label that names a command's keys goes through `shortcuts::keyed` (the words with the keys they began with, the keys swapped for the ones now) or `shortcuts::signs`, so a tooltip never names old keys. A command that shares its keys with one not offered (⌘⇧G, Find Previous while a find is open) is bound before it, and the other passes the key on (`cx.propagate`) when it has nothing to do. The terminal's own keys are not offered: they are the ones a terminal has.

New sessions shows one agent's three at a time, its mark and name at the group's head, and the agents' marks on a segmented control at the right of the section's name, where Text has its pages.

A choice is named as the agent names it, less the "(recommended)" Claude Code writes after its default (`plain_default`).

On the new-session page, a machine with neither agent on it says so over the composer and sends the person to the agents page (`no_agent_note`). It waits until the machine has been looked at.

A key is written as the Mac has it and drawn through `key_text` (`kbd_hint`, `tip`), which draws ⌘ as Ctrl off a Mac. A command whose keys may change is named through `shortcuts::keyed` or `shortcuts::signs` (Shortcuts, above).

The last section, About, says who makes Emaki. A card, the groups' ground and edge, holds the title card, set in the middle as a film's first one is: "Alkaline Software presents" (the studio at its GitHub organization until it has a site), the app's icon, its name in the face and the accent the sidebar has it in (it and the icon are each a link to emaki.lol), and the version in small gray words. Under it, a sentence naming its two owners in full, each name a link, and pills to the site, the source and the release's notes. Last, under the credits so they stay with the title card they finish, the updates, a card of two rows: Updates, with what a check found and the one button that checks or installs, and Check automatically. The row says no version, since the title card does. Tried and dropped: a row a name with a line under it saying what each is, which read as a form; the card on the bare panel, which was pale; and a plate fading from the accent, with the version on an accent chip, which the person did not want: no gradients here.

The three looks in Appearance have an icon each (`choice_icon`).

A language in Conversation's spelling group has its flag before its name (`flag_of`, drawn as a picture so it keeps its colors; the flags are drawn here, in `assets/icons/flags`).

Choices are segmented controls (`Workbench::segmented`): a muted track, the choice on a raised plate. The plate is one element under the row and slides from the old choice to the new. Each segment's bounds are recorded as the row is prepainted (`on_children_prepainted` into `seg_bounds`, relative to the track), the control remembers the choice it came from (`seg_state`), and the animation is keyed on the new choice so a click plays it once. On the first draw, before any bounds exist, the chosen segment paints its own plate so nothing flashes.

The slide belongs to the change: `seg_state` keeps when the choice changed, and a control drawn later than the slide's length has no "from". Without that, a control drawn anew (the panel opened again) was a new element whose animation started over, and the plate slid once more from a choice made long before. `segmented_sized` is the same control in a small size, used for the branch list's Recent and Name.

The scrollbar's fade lives in the vendored `scrollbar.rs` (`FADE_OUT_DELAY`, `FADE_OUT_DURATION`). The fade curve must fit its length: upstream's curve, made for a longer fade, held the bar at full strength and then cut it.

## Languages

The window speaks English, Chinese (Simplified and Traditional, told apart by script or region), Japanese, Korean, French, German and Spanish, the languages Kotoba's does, set the same way (`../kotoba/docs/window.md`, Languages). By default it follows the system: the first of its preferred languages that Emaki has (`i18n::pick`), else English. Only the window's own words change: what an agent says and names (its modes, models and efforts), what a transcript holds, what git and the system say, keys, paths and names stay as they are. So does every term the AI era coined or made common, in every language: model, agent and subagent, token, prompt, context and context window, mode, effort, thinking, tool call, artifact, MCP, hook, skill, plugin, slash command. A label that is the term is the English ("Model", "Agents", "Plan mode"), and a translated sentence holds the English word ("Context 已压缩…", "切换 model"), never 模型, エージェント, Kontext or Aufwand. German capitalizes them as nouns, all but "mode" ("die Mode" is fashion). The person asked for this. Words older than the AI era are translated: session, conversation, branch, commit, file, terminal, and a context's compacting ("Context 已压缩"); and a file's mode (its permissions) is another word.

**The language list** stands at the right of Appearance's name, in the settings window's top: System first, then under a line each language by its flag and letters (`i18n::CHOICES`: EN, ZH-CN, ZH-HK for Traditional Chinese, JA, KO, FR, DE, ES). The flags are pictures in `assets/icons/flags`, as the spelling languages' are. A choice takes at once (`Workbench::set_language`): the words are read from the table at every phrase, the menus are made again (`main::app_menus`), and the settings window fades into the new language (`lang_serial`). The main window behind it changes at its next draw, without a fade: a fade there means a new id over everything the window holds. On a Mac the choice is the app's own `AppleLanguages` in its defaults, the setting System Settings, Language & Region, Applications writes, so the two are one: what either set is what the list shows at the next launch (`i18n::chosen`). System removes it. A bare executable has no defaults of its own and follows the system. Elsewhere the settings keep it (`app.language`).

English is the key. A phrase is written in the code in English inside `t("…")`, or `tf("… {name} …", …)` with blanks, or `count(n, "{n} prompt", "{n} prompts")`, and `crates/emaki-app/locales/words.json` holds its other languages. A phrase kept in a constant is marked `phrase("…")` and drawn through `t`. Words that come from the core are put through `t` where they are drawn, and the test names the lists they come from (`core_phrases`). A sentence with links in it (About's credits) is woven from its translation (`i18n::weave`), so each language puts the links where its order wants them. A sentence is never built from translated pieces: one sentence is one phrase, its values in named blanks.

`i18n`'s tests read the sources and fail on a phrase asked for and not in the table, one in the table no longer asked for, a language missing from a phrase, or a blank that differs from the English.

The bundle declares the languages (`CFBundleLocalizations`: `macos/Info.plist`, merged by cargo-packager, and the plists `dev-app.sh` and `make-app.sh` write), so System Settings can give Emaki its own. The toolkit is told the language too (`gpui_component::set_locale`); the words of a field's menu were added to its table for the languages it lacked (`vendor/gpui-component/UPSTREAM.md`, 39).

French and German run longest: a control holds them by growing to its word (`min_w`), never by a width its English fits. Check a change in French, German and Chinese (`EMAKI_LANG`, `docs/probing.md`).

## Menus and rename

A right click opens a menu of our own. `Workbench::open_menu` puts a small card at the pointer (`render_menu`, kept inside the window, over a clear sheet any click or Escape puts away) and `menu_pick` does what was chosen (`MenuDo`). The toolkit's action-based context menu was more than a few choices needed. Every menu is made the same way, and a new one follows it: each choice has an icon in front of its words (`MenuDo::icon`, by what the choice does), and choices of one kind stand together with a line between the groups (`MenuDo::Rule`): what opens the thing, what it gives the clipboard or the message, what changes it. The card is as wide as its longest choice and no wider, the words measured before it is placed, so the room at its right is the room at its left. It settles in from just above (`MENU_IN`, keyed on the menu's serial so each opening plays once) and, put away, fades where it was (`close_menu`, `menu_gone`, `MENU_OUT`), taking no click meanwhile.

- **How a menu is laid out.** Every choice has an icon, from what it does (`MenuDo::icon`), so the words stand in one column: a spelling's correction too (replace), and a path copied is a link, apart from the thing itself copied. A menu of more than three is in groups, a line between (`MenuDo::Rule`): what opens or shows the thing, what copies it, what changes where it stands, and what changes it on disk, with what cannot be taken back (Delete, Move to Trash, Discard, Revert, Clear) last and after a line of its own. The line is a wash of the ink in the dark appearance, where the palette's border is a shade off the card and could not be seen.
- A folder, in the sidebar or on the new-session page's control, offers "Open in Finder" (`sys::OPEN_FOLDER_LABEL`) and Copy Path. The sidebar's folder is a project, so its path is the newest session's `cwd` that is still a directory; with none, the menu says the folder is gone.
- A session offers one menu wherever it is right-clicked, in the sidebar, on the sessions page and on its tab (`session_menu`): Rename; Copy Session ID and Copy Resume Command (the agent's own, after a `cd` to its folder); Open in CLI Layout, which shows the session in the agent terminal (named so, beside the shell terminal and the person's own); Open Folder and Reveal Transcript in the file manager; when it has a tab, Close Tab and Close Other Tabs; and in the sidebar Archive or Unarchive, then Delete after a line of its own. `MenuDo::Rule` is a line between groups.
- The conversation offers Copy for what is selected in it (`conversation_menu`). A right click on a word selects that word first: the toolkit's text view does word selection itself (`inline.rs`, its double click), not the window's selection layer, whose participants hold no text for a rendered document, so the right click is handled there too (`UPSTREAM.md`). The menu is opened a moment after the press (`window.defer`), once the word is selected. A right click on no text with nothing selected opens nothing.
- An attachment, as a tile in the conversation, a picture a tool read, or a chip in the composer, offers Copy Image for a picture (`attachment_menu`, `copy_image`: the file's bytes in its own format, or the bytes read back out of the transcript) and, when the file is on disk, Copy Path and Reveal. Its handler stops the press, so the conversation's own menu does not open over it.
- A text input (the composer, search, find, rename, the name, the branch field) offers Cut and Copy with a selection, Paste with something on the clipboard, and Select All (`input_menu`, `EditDo`, dispatched to the input's own focus). The toolkit would show the system's menu there; the vendored `on_secondary_click` hands the click over instead. Each of the four has its icon, as a PDF's Copy and Select All have; a spelling's corrections are words only, all of them, so they still stand in one column. On a marked word of the composer the menu is that word's corrections and nothing else (`docs/composer.md`). The input calls the handler from inside its own update, so the menu is made a moment later (`window.defer`): reading the input there aborts the app.
- A branch, on the pill in the files' head and on a row of the list, offers Copy Branch Name. The row stops the press, which would otherwise reach the list's sheet and put the list away.

A session's name is written where it was asked for (`RenameAt`, `rename_input`), in the field a file's name is written in in the tree (`name_field`): in its row of the sidebar from that row's menu, on its tab from the tab's. The name there is selected whole so a key replaces it. ↩ keeps the name and so does leaving the field, Escape leaves it as it was, an empty field changes nothing. A field opened on a session with a name on its way holds that name. Giving the name the transcript already says calls a waiting one off.

- The two are one name. Both draw the session's title, so what is written in one is what the other says, as soon as it is the title (below: at once for a session that cannot be asked, when Claude Code has taken it for one that can).
- Where there is no row and no tab to write in (the sessions page, a row in a folder that is closed, a sidebar put away) it is the sheet over a scrim it was at first (`render_rename`): a row or a tab says it drew the field (`rename_drawn`), and with neither the sheet does. There a click outside leaves the name as it was.
- A second click on the row or on the tab writes the name there, on every system (the click's count, in the row's and the tab's own click). The first has opened the session, as any click does.
- F2 does the same on Windows, wherever the keyboard is (`rename_key`, heard at the window's root, after the files tree, which keeps the key for its own row): on the tab, or in the row for a session with no tab. A Mac has no key for it. Tried and dropped: ↩ on a Mac with the keyboard on the sidebar. A click on a session puts the caret in the composer, where ↩ is the composer's, so the row had to be clicked a second time to take the keyboard before ↩ meant rename, and a click on the session showing no longer reached the composer.
- A press in a tab's field says it is taken (`press_taken`) and stops there, or it began a drag of the tab or of the window.

A name is a request, kept in `renames` and in `~/.emaki/state/titles.json` by session key until it is settled, so a quit does not lose it. For a session Claude Code can be asked about (`can_ask`) the title everywhere stays what the transcript says, and a pencil beside it on the tab, the sidebar row and the sessions page says on a hover what the name will be (`rename_mark`). `try_renames`, run when the index arrives and on the clock, types `/rename <name>` into the session's hidden terminal (`Hub::rename_in_terminal`), starting one when the session has none, once the session is between turns: not during a turn, not while a card waits for an answer, not while the turn runs in a terminal of the person's. Claude Code writes a `custom-title` row, which its resume list reads and `transcript::pick_title` puts before any AI title. It writes the same words as an `agent-name` row, which must not disqualify them.

`SessionRef::named` is the transcript's own name, and `transcript::naming` settles a request against it as each index arrives:

- The transcript says the name: it is the session's, the request is put away and the mark goes out.
- The transcript took another name since the request was made (a `/rename` typed in a terminal): the newer one stands and the request is dropped.
- Neither: it waits. One typed that the transcript still does not say once the transcript has moved on is asked for again, a few times in all, and then given up with a line under the composer. Nothing shown was wrong meanwhile, since the title was the transcript's throughout.

For a session that cannot be asked (another agent, one kept only, a folder that is gone, the hidden terminal off) the name is ours alone: laid over `SessionRef::title` at once and as each index arrives, with no mark.

A terminal types one message at a time (`Hub::type_message`), so a rename and a message sent in the same moment do not arrive as one line.

## A session begun from a folder

A folder's row in the sidebar shows a plus in place of its count while the pointer is on it (both always there, one clear, so nothing moves). It begins a session in that folder (`new_session_in`) on a tab like any other's: the conversation page with nothing said, named "New Session" in italics, the name being ours and not one anybody gave it (`unnamed`). ⌘N and the home page are as they were. ⌘T is the plus of the folder the session showing is in (`new_session_here`), and ⌘N where no session is showing. In the terminal panel ⌘T is a new terminal tab, as it was.

- It is a record of our own (`begun`), put at the head of every index until the index has one of its own for it, under a session id made here. Nothing is started and nothing is on disk.
- The first message starts Claude Code with that id (`send_message` starts where it would resume, `is_draft`), so the transcript that follows has the tab's key and the tab goes on as that session, title and all, with no hand-over.
- A session started from the home page gets the same record at its first message (`show_begun`), so its tab and its row are there at once and the message shows in it (`docs/conversation.md`). It waited for the index to find the file, on a bare pane.
- Closed with nothing sent, it is gone with its tab. It is not written to `ui.json`, since a launch would find nothing for its tab. A message typed and not sent is the composer's draft and goes with it.
- A folder's plus pressed twice goes back to the one begun and does not make a second.
- It begins with the agent last chosen for a new session, and its composer stands on the home page's tray until the first message: the folder named and not to be chosen again, the agent to be chosen (`begun_agent`). Nothing has been started, so the other agent takes the same record: the tab is re-keyed where it stands and what is typed stays. Without this a plus could only begin what the home page was last set to.
- Until its first message it has no terminal to ask anything of: its pills are the home page's (they open Settings), the composer says "Start a session…", the terminal panel's agent side says Claude Code starts with the first message, and it is not shown as live.
- Nothing starts a hidden terminal for it before that message (`terminal_check` refuses it, `warm_now` passes it by). Every other start is a resume, and `claude --resume` on an id with no transcript ends at once with "No conversation found with session ID".

## Scroll routing

macOS goes on sending wheel events after the finger lifts, addressed to wherever the pointer is by then, and gpui hands each to the scroll container under it. Its `touch_phase` tells `Started` and `Ended`, but a momentum event is just `Moved`. So a flick in one pane followed by a move to another scrolled the second.

`Workbench::route_scroll` runs in the capture phase from a raw listener a zero-size `canvas` registers at paint, before any container. Of the scrollers that name themselves (`inner_live`), the one under the pointer drawn last is the one on top and takes the gesture: a pill's list over the page, which scrolled the page while it was first. The pane under the pointer at `Started`, or at the first event after `SCROLL_GAP` (a mouse wheel sends no phases), owns the gesture. An event that lands in another pane is applied to the owner's scroll position (`ListState::scroll_by` for the conversation, a `ScrollHandle` elsewhere) and stopped. With a single pane there is nothing to do. The settings window has none of this: it is one pane, and its list occludes the page under it.

A pane is not the only thing that scrolls: a tool call's body, a box on the background commands' card, a pill's list, the search results, a PDF's page list. Each names itself at every draw (`inner_live`), and `route_scroll` looks for one under the pointer before it looks at panes:

- A gesture that begins in one is that scroller's (`scroll_inner`). The router moves it itself and stops the event, on the scroller or off it, so nothing under or beside it ever takes the rest.
- A gesture begun elsewhere and carried onto one does not move it. In a pane the event goes to the gesture's owner; on a sheet or a menu (`Inner::Over`) it goes nowhere.
- A change of layout ends the gesture under way (`end_scroll_gesture`): what is left of its momentum goes nowhere. Owned by the conversation, it went on moving the list while the CLI layout hid it, and the list came back that much further on.
- A tool call's body and a card's (`card_scroll`) are `Inner::Chained`: on the body its own handler decides (`chain_wheel`, `Stroke`: a stroke that starts at its edge is the conversation's), and off the body the gesture stays with it only if it moved it.

Scrollers that only go sideways (the terminal's tabs, a question's preview) are not named: a sideways flick moves nothing else.

## What the window remembers

`ui_state.rs` keeps `~/.emaki/state/ui.json`: bounds, the sidebar and its width, the page, the open tabs in their order and the active one, the open folders, the panels. It is written when any of that changes (bounds at most every two seconds), at quit, and when the window is closed (`save_ui_closing`), by the system's close button (`on_window_should_close`) or by Close Window and the close button the window draws on GNOME (`close_window`, whose `remove_window` asks no `should_close`): on Windows and Linux closing the window ends the app without a quit's save, and a change in its last two seconds was lost. The bounds are reused only when their center is still on a screen. They are what `window.window_bounds()` says for a window that is neither full screen nor maximized (`window_rect`), not `bounds()`: on Windows `bounds()` starts under the title bar, while gpui opens a window at a place with half its frame above it, so a window saved by `bounds()` opened half a title bar lower each launch until its foot was under the taskbar.

The page is saved but not restored: the window opens on the new-session page, and the tabs come back. `EMAKI_PAGE` and `EMAKI_OPEN` pick something else.

Scroll positions are not saved (an old `scroll` key is ignored): every open lands at the end of the conversation, which the list's bottom alignment does by itself. The list is in gpui's `FollowMode::Tail`, so it stays at the end while a reply streams in. Following pauses when the reader scrolls up, when a find hit is scrolled to, or when `pin_scroll` gives the list a real top so an opened card extends downward, and resumes once the view is back at the bottom. Without it, the list stayed anchored to the prompt while the reply grew out of sight.

## Tabs

Tabs are keys in `Workbench::tabs`. A switch is a browser's: the `Detail` left is put away whole in `stashed` (the session, the list with its scroll, what was unfolded), the one arrived at is taken out and drawn in the same frame, then read again from disk and brought up to date in place. Only a tab never shown since launch waits for its read, and the pane is empty meanwhile under tabs that stay put. A closed tab's `Detail` is let go. Tried and dropped: one `Detail`, dropped and reread at every switch, which blinked the pane and its tabs.

A folder's tabs stand together on one pill (`group_tabs`, at every draw): the segmented control's track, with a folder mark at its left end and the showing tab on a raised plate. The pills are in the order their first tabs had, a tab opened lands at the end of its folder's pill, and a session alone in its folder is a pill of one. A tab whose session is not listed yet is a pill by itself until it is. The folder is `SessionRef::project`, the sidebar's.

The plate is one element under a pill's tabs (`TabPlate`). It slides to another tab of the same pill, and between pills it fades out of one and into the other: a plate does not leave its track. It is placed by sum, never measured, since every width in the row is ours, and it reads the same clock the tabs' widths do (`TabWidth::now`), so it keeps its tab while they move.

Every tab has the same width (`sync_tab_widths`, at every draw): `TAB_MAX` while the row has room, the row less the pills' own room divided among them once it has not, down to `TAB_MIN`, which still shows a few letters of the title. Past that the tabs keep their width and the row scrolls sideways (`tabs_scroll`), as the shell's tabs do: centered while they fit, from the left once they do not, since a centered row wider than its box cannot be scrolled to its start. Both ends of the strip are one width on every page (`STRIP_END`, the pages' two buttons on one track), so the tabs keep one center line whatever stands at the ends; with each end as wide as its buttons, a page with the terminal's button at its right moved them over by half of it.

The row keeps `STRIP_GAP` clear at both ends, whatever stands there and whether the sidebar is open. A new tab grows in from nothing while the others give way, and a closed one's room is taken up the same way, over `TAB_ANIM` (`tab_widths`). A new pill's track is let out with its tab (`pill_born`), in a wrapper that clips it and stays until the plate's move is over: taken off sooner, the plate under it is a new element and plays its move again. A change in the row's own width is followed at once. The row's width is measured as it is painted (`tabs_row_w`, a `canvas` over it) and used at the next draw. Tried and dropped: tabs as wide as their titles with the flex row shrinking them, which drew a new tab at full width for a frame.

A tab is dragged to another place on its pill and no further (`on_drag` with a `DragTab`, the row's `on_drag_move` to `drag_tab_to`, which takes the place under the pointer as it moves). Its title follows the pointer on a plate (`TabGhost`) and its own tab is dimmed. The pill is dragged by its folder mark (`DragPill`, `drag_pill_to`), or by its tab when it has one, and stands after every pill whose middle the pointer has passed. Going by the middle is what keeps two pills of different widths from changing places back and forth under a pointer that is still.

Whatever a drag moves slides to its new place (`TabShift`): a tab or a pill is laid out where it now stands and drawn off it by what is left of the way, a relative `left` read off the clock, with a frame asked for at every draw while one runs (`tabs_sliding`). One moved again on its way starts from where it is. The plate adds its tab's offset, and the pill being moved is painted after the row (`deferred`, `pill_top`), so it passes over the pills it changes places with and not under them.

**The page tab.** All Sessions and Agents are one group of the row, a pill as a folder's is, with a mark of its own where a folder's has the folder (`page_tab`, `PAGE_TAB`). It holds one tab at most, which stands for whichever of the two was gone to last (`page_last`): its page's mark and name, which fade in as it changes, as a browser tab's do from one page to the next. It is clicked, dragged along the row and closed as any pill is, keeps the place a drag gave it (`page_tab_at`), and has its number for ⌘ and a digit where it stands in the row. On these two pages the strip's left end has their own two buttons where a session has the files panel's (`page_nav`): one control whose plate slides to the page gone to, each going to its page in the tab, as the sidebar's entries and ⌘L and ⌘E do, opening the tab again when it was closed. A click on the tab goes back to its page as it was left (`go_page_tab`). It is there whenever one of the two is up and stays, quiet, while a session shows, until its × or ⌘W closes it, which brings back the session shown last, or with none the new-session page (`close_page_tab`). Closing, it shrinks over `TAB_ANIM` with the gap after it (`drop_page_tab`, `page_tab_closing`), so the tabs around it slide together. The new-session page is not in it: it is the whole card, as it always was, with no tabs over it. Tried and dropped: All Sessions and Agents covering the whole card too, which hid the tabs; the tabs drawn over every page with none showing, which read as two separate places; New Session in the page tab; and the page tab pinned at the left end with the row starting there, which gave up the center line.

⌘⇧T opens the tab closed last again and shows it, and at each further press the one closed before it (`closed_tabs`, `reopen_tab`). A session begun and closed with nothing sent is not kept, one gone since or open again is passed over, and the list is the window's while it runs, not `ui.json`'s.

⌘1 to ⌘9 (Ctrl elsewhere) go to that tab in the row's order, the page tab counted where it stands, or to the last one when there are fewer (`go_tab`). ⌘ held by itself for `TAB_HINT_HOLD` shows the digits: each tab wears an outline and its number on a small plate on its lower edge. They go when the key is let go or another modifier joins it (`modifiers_changed`, from `on_modifiers_changed`). The timer from the press is answered only if that press is still the one held, so a quick ⌘C never shows them. A release the window never hears (⌘Tab away) is caught at the next draw, which asks the window what is held. The first nine tabs have a number, the one `go_tab` takes to them, and any after have none. The tab clips what it holds, so the plate is beside it in a box of the tab's size, and the outline is always there, clear until then, so nothing shifts.

## The drag region and ⌘W

The window is opened with `app_owns_titlebar_drag`, and `Workbench::drag_region` wraps the top strip and the sidebar's header. A press there becomes `start_window_move` once the pointer moves with the button down; a double click is `titlebar_double_click`. Left to AppKit, the whole strip under the transparent title bar moved the window, tabs included, so a tab could not be dragged. `press_taken` works because in gpui's bubble phase a child's listener runs before its parent's. This is how Zed's own title bar does it.

`CloseTab` closes the showing tab, then the last tab (which lands on the new-session page with the caret in its composer), then the window. `main.rs` hands a `CloseTab` no view claimed to the workbench, which does the same. `on_reopen` (a Dock click, a second launch) opens the window again, and what was typed in each composer is there (`docs/composer.md`).

Clicking a session puts the caret in the composer. On the sessions page, which draws no composer, `Workbench::render` moves the focus to the workbench's own handle whenever the composer still holds it.

## Probing

- `EMAKI_SETTINGS=<section>` opens the settings window on that section. `EMAKI_GO` steps `settings:<section>` do the same, and `setpick:<mode| model|effort>` opens that list of New sessions; with the window open `EMAKI_SHOT` takes it in place of the main window.
- `EMAKI_GO=folder:<name>` is the click on a sidebar folder. `side:<x>` drags the sidebar's edge to that x and lets go; `sidefit` is the double click on it.
- `EMAKI_GO=menu` opens the session's menu, `renaming` the rename field, `name:<words>` names it.
- `EMAKI_GO=newin:<folder's path>` is the plus on that folder.
- `EMAKI_GO=tabhints` shows the tabs' numbers with no key held. `EMAKI_GO="open:<id>;open:<id2>"` opens tabs in turn. `tabdrag:<id>:<x>` drags that tab to an x from the row's left edge, `pilldrag:<folder>:<x>` a pill. A step before the first index finds no pills, so put an `x` step first. `tabslow` before them draws the slide forty times slower, and a picture a second after the drag catches it partway. `EMAKI_SHOT_AFTER` counts from later than the steps do: 6 lands a second after a step at 10.
- `EMAKI_SCROLL_DEBUG=1` prints every wheel event with its phase and owner.
- A `mouseMoved` `CGEvent` posted to the pid moves gpui's hover. A synthetic click or press posted to the pid does not reach a click handler in a background window. The segmented plate's slide was checked with a probe build that changed the choice on a timer.
- Send real key codes (System Events `key code`, or a `CGEvent` with the right virtual key). A unicode string on virtual key 0 reaches the composer but not a single-line input.
- A synthetic `CGEvent` scroll carries `CGScrollPhase` values (began 1, changed 2, ended 4) and `CGMomentumScrollPhase` (begin 1, continue 2, end 3), not the `NSEventPhase` bits gpui reads.
- A probe copy's Claude Code is not logged in, so a rename cannot be run end to end from one.
